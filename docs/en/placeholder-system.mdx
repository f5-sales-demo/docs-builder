The form uses the shared catalog in `src/data/field-catalog.json`. Readers start
with sanitized examples and their edits follow matching fields across repositories
on `f5-sales-demo.github.io`.

## Select fields

Add a version 2 manifest at `docs/placeholders.json`. Select catalog names;
common conventions belong in the catalog rather than independent definitions.

```json
{
  "version": 2,
  "fields": ["XCSH_API_URL", "XCSH_API_TOKEN", "XCSH_NAMESPACE"],
  "groups": [
    {
      "label": "XC API",
      "keys": ["XCSH_API_URL", "XCSH_API_TOKEN", "XCSH_NAMESPACE"]
    }
  ]
}
```

Optional `examples` may override guide-specific noncredential defaults.
Catalog fields define descriptions, input types, examples, credential
classification and semantic scope. New independent settings need a catalog entry.
DNS zones, application hostnames and origins have distinct names.

## Author templates

Use `<XCSH_VARIABLE_NAME>` in code, inline code and structured examples.
Escape the opening angle bracket in ordinary MDX prose as
`\<XCSH_NAMESPACE>`. Legacy `xXCSH_VARIABLE_NAMEx` remains supported.
Ordinary `$XCSH_NAMESPACE`, `${XCSH_NAMESPACE}`, arithmetic, command
substitution and discovered identifiers remain shell expressions.

Wrap runnable blocks in a `div` with `data-xcsh-context="shell"` and a
space-separated `data-xcsh-fields` list. The browser prepends shell-quoted
exports and copies the complete displayed block. Include sanitized exports in
the static setup so Markdown readers can configure a session too.

```md
<div data-xcsh-context="shell" data-xcsh-fields="XCSH_NAMESPACE">

\`\`\`bash
printf '%s\n' "$XCSH_NAMESPACE"
\`\`\`

</div>
```

Use `data-xcsh-context="json"` and `"hcl"` for structured templates;
JSON strings escape quotes, backslashes and control characters, and HCL also
escapes interpolation introducers. Mermaid labels use encoded entities and
strict rendering. Highlighted markers can span multiple text nodes.

Keep native tool interfaces such as `TF_VAR_namespace` and map
`XCSH_NAMESPACE` into them in setup. Use `XCSH_ORIGIN_POOL_NAME` for configured names; Statistics discovers `XCSH_ORIGIN_POOL` from its load balancer. CSD maps the configured field into its existing lifecycle interface.

Query times, graph identities and API
constants remain calculated or discovered.

## Store reader edits

`f5-docs-values-v1` holds only explicit noncredential overrides in localStorage.
Matching edits follow navigation and storage events update other tabs.
Untouched fields retain their guide examples.

`f5-docs-credentials-v1` holds credentials in sessionStorage. They follow
repository navigation within one tab. Browser session restore can retain them,
and tabs opened by another tab can inherit an initial session copy. Clear
credentials explicitly when finished. Inputs are masked; copying a runnable
block includes its required credentials.

The form never submits values or sends them to a server. Storage failures retain
edits in memory for the current page. Reset shared values preserves credentials;
clear credentials preserves noncredential edits.

Known legacy records are migrated once using recorded original defaults.
Only actual overrides are promoted. Old credentials and obsolete records are
removed and credentials require re-entry.

## Preserve templates and evidence

Wrap historical outputs in `<div data-personalize="off">` with empty lines
around their code blocks. Preserve measured values, units and capture dates;
sanitize identifiers independently of personalization.

Downloaded scripts use exported configuration. A displayed script source can
declare required form fields while the download stays byte-identical.
Static Markdown, progressive machine exports and publication artifacts contain
only sanitized templates. Browser edits affect the current DOM and clipboard.

Run `node --test tests/personalization.test.mjs` and the browser acceptance
suite before delivery.
